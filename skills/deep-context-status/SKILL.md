# Deep Context status

Use this for “where are we?”, “print the plan status” or “what is up next?” Read the selected project's `START.md`, compact plan/work maps, and the selected plan and phase work sections. Avoid unrelated knowledge and verification history unless needed. This is a read-only status request; do not start work, rebuild the dashboard or change records.

Show completed, active and upcoming plans as concise linked titles. Expand the selected plan's phases in their recorded execution order with status. Expand the current phase into implemented/completed work, active work and up-next work. Explain pending user validation without presenting it as acceptance. Use recorded completion chronology when available; otherwise retain execution order and state that completion chronology is unavailable. Never invent timestamps or reorder execution based on filenames when the plan supplies an order.

Choose the plan/phase from the user's request and available context. If several genuinely fit, ask one short question naming the candidates. Keep the output scannable; honor a requested scope or format. Definitions live in `docs/requirements/plans-phases-and-work.md` inside the selected context root.
