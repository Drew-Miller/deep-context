# Project dashboard

Provide a clickable read-only dashboard on localhost for browsing the same project folders agents maintain. A user can search across projects, see the work board and priorities, open tickets, and follow links into plans, features, requirements and decisions. Show which project owns a result. Browsing leaves the underlying project documents unchanged.

Use the main content area to read work items, documentation and features, with links to related records. An active work item presents its evolving scope and links to its plan and durable requirements. Use a browsable knowledge navigation; a folder-structure screen is not needed.

## Phase and work items

The project dashboard is a phase: a developed feature idea. Its [execution plan](../../plans/000020-dashboard-plan.md) orders implementation; its [work record](../../work/active/000010-project-dashboard.md) tracks the requested work items within the phase.

Provide a dark and light appearance with an accessible toggle. Start with the system preference when the user has not chosen an appearance; remember an explicit choice in this browser when storage is available.
