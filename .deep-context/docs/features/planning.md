# Planning

Follow the canonical [plan → phase → work-item model](../requirements/plans-phases-and-work.md).

`plans/plans.md` lists the descriptive overview plans in execution order. Each plan links to phase records in `work/`; the phase's status folder shows whether it is backlog, active or completed. Several overview plans can coexist.

Use sortable six-digit ranks with gaps of ten for top-level plans. If a larger plan needs subplans, give them descriptive inherited stubs, such as `init-001-scope` and `init-001-001-detail`, with consistent sibling widths. Subplans coordinate phases and link to their execution homes.

Reordering renumbers affected branches and repairs references. When a plan or subplan completes, record its outcome and update its parent overview. Keep detailed work-item checks and implementation evidence in the phase record, with links from the plan as needed.
