### Frontmatter and generated projections

The final full-project validator parses canonical collections, rejects invalid frontmatter and duplicate IDs, checks forwarders, queue positions and selected structured references, and compares all seven generated indexes byte-for-byte with their expected renderings. The separate Markdown link scan checks trackable links. The current implementation does not prove every metadata pointer: REQ-DC-023 has a stale `code_patterns` hint (DA-07), activation validation checks path existence rather than record identity, and Active/Backlog status validation is one-way (DA-09). These semantic gaps remain even when validation passes. A body-only direct edit may leave a frontmatter-derived index unchanged; freshness of the index is not proof the body was reviewed.

The intended user route is a plain-language request to the agent, which classifies authority, updates a canonical record, invokes the bundled refresh and validation commands, and reports the outcome. Direct CLI and editor access can remain available for deliberate maintenance. Current skill and README instructions cover pieces of this flow but do not provide a complete mixed-request route or acceptance example; `deep-task` is explicit-only and should not be invoked merely to save project knowledge. This is a product proposal in DA-14, separate from any optional file watcher in DA-13.
